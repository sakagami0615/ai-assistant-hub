# Decision Twin

## 概要

Decision Twinは、grillingやbrainstormingなどの「実装前に質問を重ねる」ワークフローで、あなたの代わりに質問へ答えるSkillです。答えの根拠にするのは、あなたが過去に下した判断（判断ノート）、明示した原則、リポジトリの事実だけです。

根拠で決まらない判断や、影響が大きい判断だけをあなたに確認し、その回答を判断ノートに蓄積します。蓄積した判断は、次回以降の代理回答の根拠になります。AIの提案があなたの決定にすり替わらないことを最優先にしています。

判断がまだ少ないうちは、AIから質問を受けて答えるだけの「学習フロー」で判断ノートを増やせます。

## 利用する場面

- grillingの質問が多く、過去に決めたことを何度も答えるのが負担になっている
- リポジトリや判断ノートを調べれば分かる質問を、AIに処理させたい
- 初めて使うので、先に自分の判断の傾向をAIに覚えさせておきたい
- 代理回答がどの程度あなたの判断と一致するかを測りたい

## 仕組み

### 構成

![decision-twin の構成](assets/decision-twin/architecture.svg)

- 回答役には質問文だけを渡し、質問役の推奨や会話は渡しません。推奨に引きずられず、記録された判断だけで答えるためです。
- 回答役と検証役は`memory/`を読むだけで、書き込むのは本体だけです。

### 代理回答の流れ

![代理回答の流れ](assets/decision-twin/proxy-flow.svg)

検証役の差し戻しは1回までです。次のどれかに当てはまる質問は、承認モードにかかわらずあなたに確認します。

| # | 確認する条件 |
| --- | --- |
| 1 | 新しい約束になる |
| 2 | 元に戻せない |
| 3 | 根拠で決まらない（`UNKNOWN`） |
| 4 | 検証役が人の判断を求めた |
| 5 | 判断が矛盾している |
| 6 | 影響が大きいのに、事実か明示した判断の裏付けがない |
| 7 | 推論の確からしさが基準（既定0.80）より低い |

### 記録の強さ

答え方によって判断ノートに残る出所が変わり、次回以降にどこまで確かな根拠として扱うかが決まります。

![記録の強さ](assets/decision-twin/source-strength.svg)

AIが出した案に同意しただけの記録が、あなた自身の決定として扱われないようにするための区別です。

## 判断ノート

あなたが答えた判断を、題材ごとに1ファイルへまとめたものです。スキルフォルダ内の`memory/decisions/api.md`、`memory/decisions/db.md`のように置かれ、1つの判断が1行で書かれます。

```markdown
# API

- **一覧のページング方式**: cursor 方式にする。理由: 件数が多くても速い（2026-11-15、回答）
- **レスポンスのキー名**: snake_case にする。理由: （記載なし）（2026-11-10、学習）
```

- 残るのは今有効な判断だけです。判断を変えると該当の行が書き換わり、変更の履歴は`memory/log.jsonl`に残ります。そのため、使い続けてもファイルが際限なく増えません。
- 行末の括弧には、記録した日と出所（`回答`、`上書き`、`承認`、`自動`、`学習`）が入ります。確認質問に「同意」とだけ答えた場合の出所も`承認`で、`回答`はあなた自身の言葉で答えたときだけです。`承認`と`自動`の項目だけを根拠にした代理回答は、あなた自身の言葉ではないため、確定した判断（`EXPLICIT_DECISION`）としては扱われません。
- 手で書き足したり直したりしても構いません。同じ書式で書けば根拠として使われます。
- 見出しは判断の識別に使われるので、変えないでください。変えたいときは新しい項目として書き、古い項目の削除は`log.jsonl`の`replaces`に記録します。
- 判断が矛盾していて片方を採るときも、採らなかった方を丸ごと消さず、今回の質問の範囲だけを除く形（例: 「TODOを除く」）に書き換えます。範囲を絞れないときは、書き換え案をあなたに確認します。
- 書き換え・削除の前の行は、`log.jsonl`の`replaced_text`に残ります。

## 承認モード

代理回答をそのまま確定させるか、あなたの承認を待つかを`memory/config.json`で選べます。

```json
{"approval": "require"}
```

| 値 | 動き |
| --- | --- |
| `require`（既定） | 代理回答の一覧は、あなたが承認するまで確定しません |
| `auto` | 代理回答の一覧は自動で確定し、grillingに返ります。一覧は「自動で確定した回答」として表示されるので、後から番号を指定して上書きできます。ただし根拠のない案（`PROPOSAL`）と、`承認`・`自動`の項目だけを根拠にした推論（`INFERRED`）は自動では確定せず、`require`と同じく承認を待ちます |

- どちらのモードでも、新しい約束、元に戻せない判断、根拠がない質問などは、必ずあなたに確認します。
- 最初は`require`で使い、集計で上書きの割合が十分に低いと分かってから`auto`に切り替えることをおすすめします。

## 記憶の置き場所

記憶はすべて、スキルフォルダ内の`memory/`に置かれ、リポジトリのコードや文書には書かれません。ただし、スキルをプロジェクトの`.claude/skills/`に置くと`memory/`もリポジトリ内になります。その場合は、`memory/`をgitに入れて共有するか、`.gitignore`で外して手元だけに置くかを選んでください。

| ファイル | 内容 |
| --- | --- |
| `memory/decisions/<題材>.md` | 判断ノート。あなたの回答、上書き、承認（または自動確定）した代理回答、学習フローの回答 |
| `memory/principles.md` | あなたが承認した原則（判断の背景にある優先順位） |
| `memory/log.jsonl` | 全質問の代理回答とあなたの回答の記録（追記のみ） |
| `memory/config.json` | 任意。`approval`（承認モード）と`confidence_threshold`（確認の基準、既定は0.80） |

記憶を共有する範囲は、スキルを置く場所で決まります。

| スキルの置き場所 | 記憶の範囲 |
| --- | --- |
| プロジェクトの`.claude/skills/decision-twin/` | そのプロジェクト専用 |
| ユーザー直下の`~/.claude/skills/decision-twin/` | 全プロジェクト共通 |

- プロジェクトごとに判断を分けたいならプロジェクトに、どこでも同じ判断を使いたいならユーザー直下に置いてください。
- プラグイン経由で入れたスキルは、プラグインのキャッシュに置かれ、更新で`memory/`が消えることがあります。記憶を残したいときは、プロジェクトかユーザー直下に置いてください。
- 記憶をリセットしたいときは、`memory/`の中身（`README.md`以外）を消してください。
- スキルを入れ替えたり更新したりするときは、`memory/`を上書きしないよう注意してください。

## 導入

Claude Codeでは、初回の実行時にSkillが回答役（`twin-answerer`）と検証役（`twin-verifier`）のサブエージェント定義をコピーします。コピー先は、スキルがプロジェクトにあればそのプロジェクトの`.claude/agents/`（リポジトリ内に書かれます）、ユーザー直下にあれば`~/.claude/agents/`です。サブエージェントを使うと、回答役と検証役は読み取り専用のツール（Read、Grep、Glob）だけで動き、質問役の推奨や会話を見ずに答えます。コピーした直後は、Claude Codeを再起動すると確実に反映されます。

判断ノートがまだない場合は、学習フローから始めるか、空のまま代理回答を始めてください。空のまま始めると、最初は多くの質問があなたに確認され、答えるたびに判断ノートが増えていきます。

## 基本的な流れ

代理回答:

1. grillingなどを「decision-twinで回して」と依頼します。
2. 質問のラウンドごとに、Skillが各質問を分類し、回答役が判断ノートなどから代理回答を作ります。
3. 検証役が、回答が根拠で支持されるかを確認します。
4. 固定のルールで、あなたに確認する質問を選びます（新しい約束、元に戻せない判断、根拠がない、判断が矛盾している、高影響なのに推論しかない、など）。
5. 「確認する質問」と「代理回答の一覧」が表示されます。あなたは確認する質問に答え、一覧はまとめて承認するか、変えたい番号だけ指定します（`auto`では一覧は確定済みで、変えたい番号だけ指定します。根拠のない案は承認待ちとして別に表示されます）。
6. あなたの回答が判断ノートとログに記録され、確定した回答がgrillingに戻ります。

学習フロー:

![学習フロー](assets/decision-twin/learning-flow.svg)

1. 「decision-twinで学習したい」と依頼します。
2. AIがリポジトリを見て題材の候補を出すので、1つ選びます。
3. AIが1問ずつ質問します。選択肢の番号か自由回答で答えてください。理由も書くと、原則の候補になります。
4. 答えるたびに判断ノートに記録されます。「題材を変えて」で題材を選び直し、「終わり」で終了します。
5. 終了時に、あなたが述べた理由から原則の追記案が出ます。承認したものだけが`memory/principles.md`に書かれます。

## grill-meと組み合わせて使う

grill-me（grilling）に依頼するだけでは、Decision Twinは自動では動きません。Decision Twinは「decision-twinで答えて」のように明示されたときだけ動くように作られています。あなたが自分で答えたい場面で、AIが勝手に代わりに答えないようにするためです。

組み合わせるときは、同じ依頼文の中で両方の名前を出してください。

```text
grill-meでこの機能の設計を詰めてください。質問にはdecision-twinで答えて、必要なものだけ私に聞いてください。
```

- grill-meが出した質問をDecision Twinが受け取り、代理回答と確認する質問に振り分けます。確定した回答はgrill-meに返り、grill-meが次の質問を出します。
- grill-meが1問ずつ質問する場合も、1問だけのラウンドとして同じように処理されます。
- 承認モードが`auto`で確認する質問がない場合は、あなたの返事を待たずにgrill-meが先へ進みます。

毎回書くのが面倒な場合は、プロジェクトの`CLAUDE.md`（Codexでは`AGENTS.md`）に次の一文を書いておくと、grill-meに頼むだけでDecision Twinも使われます。

```markdown
- grill-me / grillingの質問には、常にdecision-twinを使って答える。
```

記憶が空のうちは、ほとんどの質問があなたに回ってきます。先に学習フローで判断ノートを作っておくと、代理回答で済む質問が増えます。

## 依頼例

```text
この機能の設計をgrillingで詰めたいです。質問にはdecision-twinで答えて、必要なものだけ私に聞いてください。
```

```text
decision-twinで学習したいです。このリポジトリに合った題材で質問してください。
```

```text
decision-twinのログを集計して、分類ごとのOverride Rateと自動確定の上書き率を見せてください。
```

## 注意事項

- 学習フローで答えた判断も、本番のgrillingで答えた判断と同じ重みで代理回答に使われます。迷う質問には「わからない」と答えれば記録されません。
- 判断ノートと原則には、あなたが言ったことと承認したこと（`auto`では自動確定を許したこと）だけが書かれます。AIの推測だけで原則が増えることはありません。
- サブエージェントを設置していない環境やCodexでは、回答役・検証役が別のツール制限で動かないため、独立性が弱まります。その場合はログに`isolation: "prompt-only"`と記録されます。
- ユーザー直下の共通記憶に複数のセッションが同時に書くと、判断ノートの書き換えが競合することがあります。同じ題材を同時に更新しないでください。
- 状況が変わって古い判断が合わなくなったら、一覧で上書きするか、判断ノートを直接直してください。
- 集計結果（`scripts/report.py`）は、承認モードを`auto`にしてよいかを判断する材料です。Escalation Recall / Precisionは近似値です。
