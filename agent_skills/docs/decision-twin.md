# Decision Twin

## 概要

Decision Twinは、grillingやbrainstormingなどの「実装前に質問を重ねる」ワークフローで、あなたの代わりに質問へ答えるSkillです。答えの根拠にするのは、あなたが過去に下した判断（判断ノート）、明示した原則、リポジトリの事実だけです。

根拠で決まらない判断や、影響が大きい判断だけをあなたに確認し、その回答を判断ノートに蓄積します。蓄積した判断は、次回以降の代理回答の根拠になります。AIの提案があなたの決定にすり替わらないことを最優先にしています。

判断がまだ少ないうちは、AIから質問を受けて答えるだけの「学習フロー」で判断ノートを増やせます。

## 利用する場面

- grillingの質問が多く、過去に決めたことを何度も答えるのが負担になっている
- リポジトリや判断ノートを調べれば分かる質問を、AIに処理させたい
- 初めて使うので、先に自分の判断の傾向をAIに覚えさせておきたい
- 代理回答がどの程度あなたの判断と一致するかを測りたい

## 判断ノート

あなたが答えた判断を、題材ごとに1ファイルへまとめたものです。スキルフォルダ内の`memory/decisions/api.md`、`memory/decisions/db.md`のように置かれ、1つの判断が1行で書かれます。

```markdown
# API

- **一覧のページング方式**: cursor 方式にする。理由: 件数が多くても速い（2026-11-15、回答）
- **レスポンスのキー名**: snake_case にする。理由: （記載なし）（2026-11-10、学習）
```

- 残るのは今有効な判断だけです。判断を変えると該当の行が書き換わり、変更の履歴は`memory/log.jsonl`に残ります。そのため、使い続けてもファイルが際限なく増えません。
- 行末の括弧には、記録した日と出所（`回答`、`上書き`、`承認`、`自動`、`学習`）が入ります。
- 手で書き足したり直したりしても構いません。同じ書式で書けば根拠として使われます。

## 承認モード

代理回答をそのまま確定させるか、あなたの承認を待つかを`memory/config.json`で選べます。

```json
{"approval": "require"}
```

| 値 | 動き |
| --- | --- |
| `require`（既定） | 代理回答の一覧は、あなたが承認するまで確定しません |
| `auto` | 代理回答の一覧は自動で確定し、grillingに返ります。一覧は「自動で確定した回答」として表示されるので、後から番号を指定して上書きできます |

- どちらのモードでも、新しい約束、元に戻せない判断、根拠がない質問などは、必ずあなたに確認します。
- 最初は`require`で使い、集計で上書きの割合が十分に低いと分かってから`auto`に切り替えることをおすすめします。

## 記憶の置き場所

記憶はすべて、スキルフォルダ内の`memory/`に置かれます。リポジトリ側には何も書きません。

| ファイル | 内容 |
| --- | --- |
| `memory/decisions/<題材>.md` | 判断ノート。あなたの回答、上書き、承認（または自動確定）した代理回答、学習フローの回答 |
| `memory/principles.md` | あなたが承認した原則（判断の背景にある優先順位） |
| `memory/log.jsonl` | 全質問の代理回答とあなたの回答の記録（追記のみ） |
| `memory/config.json` | 任意。`approval`（承認モード）と`confidence_threshold`（確認の基準、既定は0.80） |

記憶を共有する範囲は、スキルを置く場所で決まります。

| スキルの置き場所 | 記憶の範囲 |
| --- | --- |
| プロジェクトの`.claude/skills/decision-twin/` | そのプロジェクト専用 |
| ユーザー直下の`~/.claude/skills/decision-twin/` | 全プロジェクト共通 |

- プロジェクトごとに判断を分けたいならプロジェクトに、どこでも同じ判断を使いたいならユーザー直下に置いてください。
- 記憶をリセットしたいときは、`memory/`の中身（`README.md`以外）を消してください。
- スキルを入れ替えたり更新したりするときは、`memory/`を上書きしないよう注意してください。

## 導入

Claude Codeでは、初回の実行時にSkillが回答役（`twin-answerer`）と検証役（`twin-verifier`）のサブエージェント定義をコピーします。コピー先は、スキルがプロジェクトにあればそのプロジェクトの`.claude/agents/`、ユーザー直下にあれば`~/.claude/agents/`です。サブエージェントを使うと、回答役は読み取り専用のツールだけで動き、質問役の推奨や会話を見ずに答えます。コピーした直後は、Claude Codeを再起動すると確実に反映されます。

判断ノートがまだない場合は、学習フローから始めるか、空のまま代理回答を始めてください。空のまま始めると、最初は多くの質問があなたに確認され、答えるたびに判断ノートが増えていきます。

## 基本的な流れ

代理回答:

1. grillingなどを「decision-twinで回して」と依頼します。
2. 質問のラウンドごとに、Skillが各質問を分類し、回答役が判断ノートなどから代理回答を作ります。
3. 検証役が、回答が根拠で支持されるかを確認します。
4. 固定のルールで、あなたに確認する質問を選びます（新しい約束、元に戻せない判断、根拠がない、判断が矛盾している、高影響なのに推論しかない、など）。
5. 「確認する質問」と「代理回答の一覧」が表示されます。あなたは確認する質問に答え、一覧はまとめて承認するか、変えたい番号だけ指定します（`auto`では一覧は確定済みで、変えたい番号だけ指定します）。
6. あなたの回答が判断ノートとログに記録され、確定した回答がgrillingに戻ります。

学習フロー:

1. 「decision-twinで学習したい」と依頼します。
2. AIがリポジトリを見て題材の候補を出すので、1つ選びます。
3. AIが1問ずつ質問します。選択肢の番号か自由回答で答えてください。理由も書くと、原則の候補になります。
4. 答えるたびに判断ノートに記録されます。「題材を変えて」で題材を選び直し、「終わり」で終了します。
5. 終了時に、あなたが述べた理由から原則の追記案が出ます。承認したものだけが`memory/principles.md`に書かれます。

## 依頼例

```text
この機能の設計をgrillingで詰めたいです。質問にはdecision-twinで答えて、必要なものだけ私に聞いてください。
```

```text
decision-twinで学習したいです。このリポジトリに合った題材で質問してください。
```

```text
decision-twinのログを集計して、分類ごとのOverride Rateと自動確定の上書き率を見せてください。
```

## 注意事項

- 学習フローで答えた判断も、本番のgrillingで答えた判断と同じ重みで代理回答に使われます。迷う質問には「わからない」と答えれば記録されません。
- 判断ノートと原則には、あなたが言ったことと承認したこと（`auto`では自動確定を許したこと）だけが書かれます。AIの推測だけで原則が増えることはありません。
- サブエージェントを設置していない環境やCodexでは、回答役・検証役が別のツール制限で動かないため、独立性が弱まります。その場合はログに`isolation: "prompt-only"`と記録されます。
- 状況が変わって古い判断が合わなくなったら、一覧で上書きするか、判断ノートを直接直してください。
- 集計結果（`scripts/report.py`）は、承認モードを`auto`にしてよいかを判断する材料です。Escalation Recall / Precisionは近似値です。
