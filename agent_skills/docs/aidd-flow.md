# AIDD Flow

## 概要

AIDD Flowは、AIとの対話で整理した開発内容を、レビュー可能なプロダクトドキュメントとして残し、その内容を起点にテスト先行で実装するためのSkillです。

会話や一時的な計画だけで開発を進めず、目的、要求、仕様、設計、検証観点をMarkdownへ反映します。新規プロジェクトの立ち上げと、既存プロジェクトへの機能追加の両方に利用できます。

## 利用する場面

- アイデアから新しいアプリケーションを設計・実装したい
- ユーザーストーリーやEpicから具体的な仕様を作りたい
- AIとの会話で決まった内容を、後から確認できる形で残したい
- 仕様とテストケースを対応させ、テストを先に書いて実装したい
- 既存プロジェクトのドキュメントと実装を一緒に更新したい

## 実施前の準備

AIDD Flowを始める前に、プロジェクト全体で守るルールを、利用するAIエージェントが作業開始時に自動で読み込む指示ファイルへ記載しておくことを推奨します。

指示ファイルの名前や配置場所は利用するツールによって異なります。代表例には、`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.github/instructions/*.instructions.md`などがあります。利用するツールの仕様を確認し、リポジトリのルートまたはルールを適用したいディレクトリへ配置してください。

記載するルールの例は次のとおりです。

- 使用する言語、フレームワーク、パッケージ管理方法
- コーディング規約、命名規則、ディレクトリ構成
- 実行するテスト、静的解析、フォーマットのコマンド
- 編集してよい範囲と、変更してはいけないファイル
- セキュリティ、機密情報、依存関係更新に関する方針
- Git操作、コミット、レビューに関するルール
- プロジェクト固有の用語や設計上の制約

これらを先に明文化しておくと、AIDD Flowで作成するドキュメント、実装、テストがプロジェクトの方針から外れにくくなります。プロダクトの目的や機能要求は`docs/product/`へ記載し、作業方法やリポジトリ運用のルールはエージェント向け指示ファイルへ記載する、と役割を分けると管理しやすくなります。

## 作成するドキュメント

プロダクトの正本となる資料は`docs/product/`へ配置します。

```text
docs/product/
  concept.md
  user-stories.md
  epics/
    <epic-name>.md
  specs/
    <spec-name>.md
  domain-model.md
  diagram.md
  test-plan.md
  test-cases.md
```

| ドキュメント | 内容 |
| --- | --- |
| `concept.md` | 目的、対象ユーザー、課題、ゴール、非ゴール、成功条件 |
| `user-stories.md` | ペルソナとユーザーストーリー |
| `epics/*.md` | 開発単位ごとの要求、制約、受け入れ条件 |
| `specs/*.md` | フィールド、振る舞い、検証、エラーなどの具体仕様 |
| `domain-model.md` | 中核概念、関係、不変条件、ライフサイクル |
| `diagram.md` | コンテキスト図、コンポーネント図、シーケンス図など |
| `test-plan.md` | テスト全体の戦略と検証範囲 |
| `test-cases.md` | 仕様に対応する具体的なテストケース |

設計中の作業用資料は、正本と分けて`docs/planning/`へ配置します。

```text
docs/planning/
  specs/
  plans/
```

## 基本的な流れ

1. 既存のコード、ドキュメント、作業用資料を確認します。
2. AIとの対話で目的、対象範囲、要求、未決事項を整理します。
3. 必要なプロダクトドキュメントを作成または更新します。
4. ドキュメント間のリンク、用語、要求、仕様の整合性を確認します。
5. 実装する場合は、テスト方針とテストケースを先に定義します。
6. 失敗するテストを確認してから最小限の実装を行います。
7. 実装中に仕様との差異が見つかった場合は、ドキュメントへ戻って修正します。

## 依頼例

```text
aidd-flowを使って、Pythonで個人向けToDoリストを設計し、実装してください。
```

```text
aidd-flowを使って、このプロジェクトにユーザー認証機能を追加してください。
既存のdocs/productを確認し、影響するドキュメントだけを更新してください。
```

```text
このEpicからSpec、テスト方針、テストケースを作成してください。
実装にはまだ進まないでください。
```

## 特徴と注意事項

- ドキュメント作成では、不明な要求を推測で確定せず、必要に応じて利用者へ確認します。
- すべてのテンプレート項目を機械的に埋めるのではなく、対象機能に必要な内容を選びます。
- 実装まで行う場合は、仕様とテストケースの対応を維持します。
- 作業用の設計書や計画書は、`docs/product/`の正本として扱いません。
- 小規模な設定変更など、プロダクト仕様に影響しない作業では、不要な正本ドキュメントを増やしません。
