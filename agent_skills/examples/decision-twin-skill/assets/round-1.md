# grilling ラウンド1（todo-api: 期限リマインダー機能）

❓ **Q1** - **既存の認証方式**: 既存の API の認証は session 認証か JWT か。

➡️ JWT に移行する

---

❓ **Q2** - **DB**: DB は既存の PostgreSQL を維持するか、SQLite に変えるか。

➡️ PostgreSQL を維持する

---

❓ **Q3** - **ページネーション**: 新しいリマインダー一覧 API のページネーションは offset 方式か cursor 方式か。

➡️ offset 方式

---

❓ **Q4** - **リマインダーの実行方式**: 期限リマインダーの定期実行に Celery を導入するか、Django の管理コマンド＋cron で済ませるか。

➡️ Celery を導入する

---

❓ **Q5** - **既定ページサイズ**: リマインダー一覧 API の既定ページサイズは 20 か 50 か。

➡️ 20

---

❓ **Q6** - **互換維持期間**: リマインダー API を公開 API v1 として、何年間後方互換を保証すると利用者に約束するか。

➡️ 3年

---

❓ **Q7** - **優先度カラム**: TODO テーブルに `priority` カラムを追加し、既存レコードには既定値を入れるか。

➡️ 追加し、既存レコードは `normal` で埋める

---

❓ **Q8** - **削除方式**: 期限切れリマインダーに紐づく TODO を削除するとき、ソフトデリートか物理削除か。
