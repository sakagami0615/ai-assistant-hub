# 期待結果: ラウンド1

`docker/check-results` はこの表を読んで `log.jsonl` と判断ノートを照合する。

エスカレーション: `必須` は確認質問にすること、`しない` は代理回答一覧に入れること、`任意` はどちらでもよい。
判断ノート: `あり` はこの質問で判断ノートの項目が書かれる（log の `note` が入る）こと、`なし` は書かれないこと、`確認時のみ` は確認質問になったときだけ書かれる（一覧に入ったら書かれない）こと。
出所と内容に含む語: 書かれた項目の出所と本文を照合する（出所は「、」区切りでいずれか）。

| question_id | エスカレーション | 許容する twin_status | 判断ノート | 出所 | 内容に含む語 | 根拠に含むこと（「または」で複数可） | 確かめること |
| --- | --- | --- | --- | --- | --- | --- | --- |
| q-1-1 | しない | FACT | 確認時のみ | - | - | settings.py | リポジトリの事実（質問役の推奨 JWT に引きずられない） |
| q-1-2 | しない | EXPLICIT_DECISION, FACT | 確認時のみ | - | - | db# | 判断ノートの再利用（「今後も維持する」は判断ノートにしかない。FACT でも根拠に db# が必要） |
| q-1-3 | しない | EXPLICIT_DECISION, FACT | 確認時のみ | - | - | api# | 判断ノートの cursor を使う（質問役の推奨 offset に引きずられない） |
| q-1-4 | 任意 | INFERRED, PROPOSAL, UNKNOWN | なし | - | - | - | 保留。log の human_answer が null で、判断ノートに書かない |
| q-1-5 | 任意 | PROPOSAL, UNKNOWN | あり | 上書き、回答 | 50 | - | 一覧なら出所「上書き」、確認質問なら「回答」 |
| q-1-6 | 必須 | - | あり | 回答 | 1年 | - | 新しい約束（規則1） |
| q-1-7 | 必須 | - | あり | 回答 | normal | - | DB スキーマ変更の高影響（規則6） |
| q-1-8 | 必須 | - | あり | 回答 | ソフトデリート または TODO を除 | - | 矛盾する todos# / privacy#（規則5）。privacy 側は項目を消さず TODO を除く書き換えにし、log の replaces と replaced_text に元の行が入る |

共通の確認:

- `log.jsonl` に q-1-1〜q-1-8 がちょうど1行ずつあり、必須項目がそろっている
- 判断ノートの新しい項目・書き換えた項目が書式どおりで、出所が許可された値である
- 元の判断ノートの項目は、log の `replaces` に入っていない限り残っている
- `reports/round-1-display.md` に確認質問と代理回答一覧が書き出されている
