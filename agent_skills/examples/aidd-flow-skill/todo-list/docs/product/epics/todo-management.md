# ToDo管理

## 概要

個人利用者が一画面でToDoを登録、確認、進捗更新、削除できる機能を提供する。

## 関連ユーザーストーリー

- [US-001: ToDoを登録する](../user-stories.md#us-001-todoを登録する)
- [US-002: ToDoを確認する](../user-stories.md#us-002-todoを確認する)
- [US-003: 進捗を更新する](../user-stories.md#us-003-進捗を更新する)
- [US-004: 不要なToDoを削除する](../user-stories.md#us-004-不要なtodoを削除する)

## 機能要求

- FR-001: タイトルを指定してToDoを追加できる。
- FR-002: ToDoを作成日時の新しい順で一覧表示できる。
- FR-003: 各ToDoのステータスを未着手、進行中、完了から選択できる。
- FR-004: ToDoを削除できる。
- FR-005: ToDoが存在しない場合に空状態を表示する。

## 非機能要求

- NFR-001: データをSQLiteへ永続化する。
- NFR-002: 状態変更操作をCSRFから保護する。
- NFR-003: 主要な正常系と異常系を自動テストで検証する。

## 設計制約

- PythonとDjangoを使用する。
- Python 3.14の通常版公式Dockerイメージ`python:3.14`を使用する。
- 依存関係と仮想環境はuvで管理する。
- アプリケーション、依存同期、テスト、静的検査はDocker Compose内で実行する。
- SQLiteファイルはDockerの名前付きボリュームへ保存する。
- Djangoテンプレートと関数ベースビューを使用する。
- ログイン機能を設けない。

## 受け入れ条件

- 有効なタイトルでToDoを追加すると、未着手として一覧に表示される。
- 一覧は作成日時の新しい順で表示される。
- 任意のToDoを3種類のステータスのいずれにも変更できる。
- 任意のToDoを削除できる。
- 空白だけのタイトルと不正なステータスは保存されない。
- 存在しないToDoへの更新と削除は404になる。

## 対象外

- 編集、期限、優先度、タグ、検索、絞り込み
- 複数ユーザー対応
- REST APIと非同期更新
