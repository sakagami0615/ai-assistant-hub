# ToDo管理仕様

## 元になった要求

- [ToDo管理 Epic](../epics/todo-management.md)のFR-001からFR-005、NFR-001からNFR-003

## 概要

ログインなしの単一画面で、ToDoの一覧表示、追加、ステータス変更、削除を提供する。

## フィールド / パラメーター

### Todo

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `id` | 整数 | 自動 | 主キー |
| `title` | 文字列 | 必須 | 最大200文字、空白のみ不可 |
| `status` | 文字列 | 必須 | `NOT_STARTED`、`IN_PROGRESS`、`COMPLETED`のいずれか |
| `created_at` | 日時 | 自動 | 作成時に設定 |

### HTTP入力

| 操作 | メソッド | パラメーター |
| --- | --- | --- |
| 一覧表示 | GET | なし |
| 追加 | POST | `title` |
| ステータス変更 | POST | URL内の`todo_id`、フォームの`status` |
| 削除 | POST | URL内の`todo_id` |

## 振る舞い

- 一覧は`created_at`の降順で表示する。
- 0件の場合は「ToDoはまだありません。」と表示する。
- 有効なToDoを追加すると、`status`を`NOT_STARTED`として保存する。
- 各ToDoには現在のステータスを選択したプルダウンを表示する。
- ステータス変更では3種類の許可値から任意の状態を指定できる。
- 追加、ステータス変更、削除の成功後は一覧URLへリダイレクトする。
- 削除したToDoは一覧とDBから除かれる。

## 検証

- タイトルは前後の空白を除去して保存する。
- 空文字または空白のみのタイトルは登録しない。
- タイトルは200文字以下とする。
- ステータスは定義済みの3値だけを許可する。
- 状態変更操作には有効なCSRFトークンを要求する。

## 実行環境

- ベースイメージは通常版の`python:3.14`を使用する。
- Python依存関係はコンテナ内のuvで同期する。
- Django開発サーバーはDocker Composeから起動する。コンテナ内部では8000番ポートを使用し、ホスト側は環境変数`TODO_PORT`で指定する。未指定時は8000番ポートを使用する。
- ソースコードはホストからコンテナの`/app`へマウントする。
- SQLiteファイルは名前付きボリュームをマウントした`/data/db.sqlite3`へ保存する。
- コンテナ起動時にマイグレーションを適用してから開発サーバーを起動する。
- LAN内の別PCからアクセスする場合は、許可するIPアドレスまたはホスト名を環境変数`DJANGO_ALLOWED_HOSTS`へカンマ区切りで指定する。未指定時は`localhost`と`127.0.0.1`のみを許可する。

## エラー

- 追加時のタイトル検証エラーはHTTP 200で一覧画面を再表示し、入力欄の近くに表示する。
- 存在しない`todo_id`のステータス変更または削除はHTTP 404を返す。
- 不正な`status`はHTTP 400を返し、現在値を変更しない。
- ステータス変更または削除へのGETはHTTP 405を返す。

## 例

- タイトル「設計書を確認する」を追加すると、未着手のToDoとして表示される。
- ステータスに`IN_PROGRESS`を送信すると、表示が「進行中」になる。
- タイトルに半角空白だけを送信すると、エラーが表示されToDoは増えない。
