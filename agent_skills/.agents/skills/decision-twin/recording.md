# decision-twin の記録ルール

判断記録は「ユーザーが言ったこと」と「ユーザーが承認したこと（承認モード auto ではユーザーが自動確定を許したこと）」だけでできている状態を保つ。AI の推測だけで判断ノートや原則を書かない。

## log.jsonl

- 全質問について1問1行を追記する。学習フローの質問も1問1行。形式は [formats.md](formats.md)。
- 追記だけを行う。既存の行は書き換えも削除もしない。集計と判断の履歴の土台になるため。

## 判断ノートを書く場面

| 場面 | 出所 |
| --- | --- |
| エスカレーション質問にユーザーが自分の言葉で答えた（twin の案と違う答えでも。`上書き` は一覧の回答を変えたときだけ） | `回答` |
| エスカレーション質問に「同意」だけで答えた（➡️ の推奨を認めた。twin の推奨なら根拠 id 付き） | `承認` |
| 代理回答一覧の回答をユーザーが上書きした（auto で自動確定した後の上書きを含む） | `上書き` |
| 一覧の `INFERRED` / `PROPOSAL` をユーザーが承認した（承認待ちが後から承認された場合を含む） | `承認` |
| 承認モード auto で `INFERRED` が自動確定した（承認待ちの対象は自動確定せず、承認されれば `承認`） | `自動` |
| 学習フローでユーザーが答えた | `学習` |

出所 `回答` はユーザーが自分の言葉で答えたときに限る。推奨に同意しただけの回答が、一覧の承認より強い根拠として残ってはならない。

確認質問になった質問は、status に関係なく判断ノートに書く。次のものは書かない。

- 一覧に入った `FACT` と `EXPLICIT_DECISION`（再調査・参照できるため）
- 保留した質問、承認されていない代理回答
- 学習フローで「わからない」「どちらでもいい」「今は決めない」と答えた質問

## 判断ノートの書き方

- 置き場所はこのスキルフォルダの `memory/decisions/<topic>.md`。テンプレートは [assets/templates/decision-note.md](assets/templates/decision-note.md)。
- 題材ファイルは、既存ファイルの見出しと項目から合うものを選ぶ。合うものがなければ新しく作る（`<topic>` は英語ケバブケース、見出しは日本語の表示名）。
- 1項目1行で書く。

  ```
  - **<判断の見出し>**: <決めたこと>。理由: <理由>（YYYY-MM-DD、<出所>[、根拠: <id>, ...]）
  ```

  - 見出しは、何についての判断かが分かる短い名詞句にし、ファイル内で一意にする。参照 id は `<topic>#<見出し>`。
  - 「理由」にはユーザーが述べた理由だけを書く。述べていなければ「（記載なし）」。
  - 日付は記録した日。`承認`・`自動` のときだけ、代理回答の根拠 id を `、根拠: ` の後に並べる。
- 見出しは変えない（id が log の `note` / `replaces` と対応しているため）。見出しを変えたいときは新しい項目として書き、古い項目を `replaces` に入れる。
- 同じ判断が既にあり内容が変わるときは、その行を書き換える。古い内容は残さない。log の `replaces` に元の id、`replaced_text` に書き換え前の行の文面を入れる（同じ順）。
- 矛盾（規則5）を解消する回答では、採った方の項目を書き換え（または新しく書き）、採らなかった方の項目は、質問の範囲だけを除く書き換え（例: 「TODO を除く」）にする。項目全体を消さない。書き換えた項目の id を `replaces` に入れる。範囲を絞れない場合や、書き換えがユーザーの回答から明らかでない場合は、書き換え案をユーザーに提示し、承認を得てから書く。
- 書き換える前にファイルを読み直し、読み直した内容に対して書き換える（複数セッションが同じ記憶に書くことがあるため）。

## 原則の追記

1. ユーザーが回答の中で一般化できる理由（例:「外部公開する API は互換性を優先する」）を述べたときだけ、追記案を作る。AI の推測で一般化を足さない。
2. 追記案はラウンドの記録の最後（学習フローでは終了時）にまとめて提示し、文言そのものの承認を求める。修正があれば修正後の文言を使う。
3. 承認された案を `memory/principles.md` に次の形で追記する。ファイルがなければ作る。

   ```
   - <原則1行>（出典: api#公開 API の互換維持期間、2026-11-15）
   ```

4. 承認されなかった案は書かず、log に `principle_rejected` の行を残す。
