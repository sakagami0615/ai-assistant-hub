# agent_skills

AIエージェント向けSkillを作成・配布するディレクトリ。Skillを追加・変更するときは、以下のルールに従う。

## フォルダ構成

1つのSkillは、次の3か所をセットで作成する。`<name>`はSkillの`name`と同じケバブケースにする。

```text
agent_skills/
├── .agents/skills/<name>/   # Skill本体（配布単位）
│   ├── SKILL.md
│   ├── <reference>.md       # 必要な分岐でだけ読む補足資料
│   └── assets/templates/    # Skillが生成するファイルのテンプレート
├── docs/<name>.md           # 利用者向けの説明
└── examples/<name>-skill/   # 利用例
```

- `.agents/skills/<name>/`には配布するものだけを置く。作成ルールや設計メモは置かない。
- 設計書・計画書などの作業用ドキュメントは`@workdir/docs/`（git管理外）に置く。
- コミット対象は上記3か所と、このディレクトリの共通ファイルに限る。

## SKILL.md

- フロントマターは`name`と`description`を持つ。`description`には、Skillを使うべき状況（発動条件）を書く。
- 本文は手順を先頭に置き、一部の場合にしか使わない参照情報は同じフォルダの別ファイルへ分けて、本文からリンクする。
- 作成・編集時は`writing-for-agents`の指針に沿って書く。

## docs/<name>.md

利用者（人）が読む説明書。です・ます調で書く。

- 見出しは`# <Skill表示名>`とし、次の節をこの順で必ず含める。
  1. `## 概要`: 何をするSkillか、何を重視するか
  2. `## 利用する場面`: 箇条書き
  3. `## 基本的な流れ`: 番号付きリスト
  4. `## 依頼例`: `text`コードブロックで、そのまま貼り付けられる依頼文を2〜3個
  5. `## 関連ファイル`: Skill本体、補足資料、利用例への相対リンク
- Skill固有の内容（確認対象、作成するドキュメント、注意事項など）は、「利用する場面」と「依頼例」の間、または「依頼例」と「関連ファイル」の間に節を追加する。
- SKILL.mdの内容を書き写さない。利用者が判断に使う情報（何ができるか、どう頼むか、何に注意するか）に絞る。

## examples/<name>-skill/

Skillを実際に動かした結果、または動作を確認する仕組みを置く。どちらかの形にする。

- **出力サンプル型**: Skillを使って作った成果物そのもの（例: `aidd-flow-skill/todo-list/`）。`examples/<name>-skill/<題材>/`に置き、題材の`README.md`に起動方法を書く。
- **検証ハーネス型**: Skillをコンテナ内で実行し、結果を確認する仕組み（例: `cve-check-skill/`）。入力は`assets/`、期待結果は`assets/`内の`expected-*.md`、実行結果は`reports/`（中身はgit管理外）に置く。

共通ルール:

- 実行環境はDocker Composeで完結させ、ホストに依存ツールをインストールさせない。
- ホストのポートは環境変数で変更できるようにする。8080、8081、3001は他のプロジェクトが使っているため、既定値には18080番台などを使う。
- 追加・変更したら、Composeで実際に起動・実行して動くことを確認する。
